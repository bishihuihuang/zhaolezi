# 发布指南：把本站上传到 GitHub Pages

> 本地仓库已经建好并提交完毕（**未配置远程、未推送**），要推的就是 `上线网页\` 这个文件夹。
> 你只需要做三件事：**建仓库 → 绑远程 → 推送**。全程约 5 分钟。
> 平时更新不用看这份，双击顶层的「一键发布到GitHub.bat」即可。
> 站内 **C5「网站托管与 GitHub Pages」** 讲了同样内容的原理版，可对照学习。
>
> 目录提示：站点源码在 `原版源文件\`，构建与测试脚本在 `构建工具\`，
> 一键发布脚本和「说明.txt」在顶层，真正要推的仓库是 `上线网页\`。

## 第 0 步：确认本地状态

在 `E:\上传网页\现代化\上线网页` 打开命令行（文件夹地址栏输入 `cmd` 回车），执行：

```bash
git log --oneline -5
```

能看到提交记录（如 `… v1.5.0 发布根初始提交`）说明本地仓库正常。

## 第 1 步：在 GitHub 网页新建空仓库

1. 打开 https://github.com/new （需先登录，账号即你现有的 bishihuihuang）
2. Repository name 填：**`xiandaihua`**（建议；用其他名字也行，见下方"换仓库名"）
3. 可见性选 **Public**（免费账户的 GitHub Pages 需要 Public）
4. **不要**勾选 "Add a README"、".gitignore"、"license"（本地已有，勾了会冲突）
5. 点 **Create repository**

## 第 2 步：绑定远程并推送

回到命令行，依次执行（复制时确认是同一行）：

```bash
git remote add origin https://github.com/bishihuihuang/xiandaihua.git
git push -u origin main
```

- 第一次推送会弹出 GitHub 登录窗口，按提示登录授权即可
- 推送成功会显示 `main -> main` 字样

以后更新站点：改 `原版源文件\` 里的页面 → 双击顶层的「一键发布到GitHub.bat」。
脚本会自动跑体检、同步到 `上线网页\`、提交、推送，全程不用敲命令。

## 第 3 步：开启 GitHub Pages

1. 打开仓库页面 → **Settings** → 左侧 **Pages**
2. Build and deployment → Source 选 **Deploy from a branch**
3. Branch 选 **main**、Folder 选 **`/(root)`** → Save
4. 等 1~2 分钟，刷新页面出现绿条提示后访问：

```
https://bishihuihuang.github.io/xiandaihua/
```

> 这里和本站的目录结构有关：`上线网页\` 本身就是 GitHub 仓库，站点文件直接躺在仓库根，
> 所以 Pages 目录必须选 `/(root)`。选成别的子文件夹线上会是 404。

## 换仓库名怎么办？

如果第 1 步用了别的仓库名（比如 `learn-modern`）：

1. 把 `构建工具\_构建.js` 顶部的 `const REPO = 'xiandaihua';` 改成新名字
2. 顶层「一键发布到GitHub.bat」里的 `set "REPO=..."` 也改成新名字
3. 运行 `node 构建工具\_构建.js`（sitemap/robots 里的网址会全部更新）
4. 远程地址相应改为 `https://github.com/bishihuihuang/learn-modern.git`

## 本地检查（可选但推荐）

改动较大时，发布前先过两道闸门。**两条命令不要同时跑**，会互相抢 CPU 导致 node 直接崩溃：

```bash
node 构建工具\_构建.js        # 静态体检：语法 / 内链 / 目录一致性，必须 exit 0
node 构建工具\serve.js        # 另一窗口起本地预览 http://127.0.0.1:8866
node 构建工具\smoke.js        # 127 页真实执行脚本，约 60~200 秒，必须全绿
```

## 常见报错对照

| 报错关键词 | 原因 | 解决 |
|---|---|---|
| `rejected ... fetch first` | 远程有本地没有的提交（比如网页上勾了 README） | `git pull --rebase origin main` 后重推 |
| `Authentication failed` | 登录凭据过期 | 控制面板→凭据管理器→Windows 凭据→删除 `git:https://github.com` 条目后重推，重新登录 |
| `not a git repository` | 命令行的当前目录不对 | 必须在 `上线网页\` 里执行，不是顶层 |
| `Cannot find module 'jsdom'` | 冒烟测试依赖缺失 | 进 `构建工具\` 跑 `npm install` |
| `EADDRINUSE :8866` | 预览端口被占 | 关掉之前的 serve.js 窗口再开 |
| `Could not resolve host` | 网络不通/代理问题 | 检查网络或关闭代理后重试 |
| Pages 打开 404 | 分支/目录选错，或未等部署完成 | Settings→Pages 确认 main + `/(root)`，等 2 分钟 |
| 页面样式丢失 | 通过 file:// 双击打开 | 正常现象；用上面的线上地址访问 |
| 更新后没变化 | Service Worker 缓存 | 等 1 分钟后普通刷新（新 SW 会自动接管），或 Ctrl+F5 强刷一次 |
| 报"不是内部或外部命令" | 没装 Node.js | 去 https://nodejs.org 装 LTS 版 |

## 关于隐私

推送到 Public 仓库的内容全网可见。本站不含任何密钥、密码或个人信息；
`git log` 中的提交邮箱会显示在提交记录里，介意可执行
`git config user.email "bishihuihuang@users.noreply.github.com"` 后再提交。

## 别碰的东西

- **不要改 `上线网页\` 里的文件**——每次构建会由 `原版源文件\` 整份覆盖，手改会被冲掉。
- **不要删 `上线网页\.git\`**——那就是 GitHub 仓库本体。
  （`_构建.js` 的同步步骤已跳过点开头的目录，不会误删）
- **不要删 `构建工具\node_modules\`**——冒烟测试依赖 jsdom，删了要重新 `npm install`。
- **不要手改** `service-worker.js` 的 ASSETS/CACHE_VERSION、`sitemap.xml`、`robots.txt`——都是构建生成的。
