一、F12 是什么

浏览器自带的开发者工具（DevTools），按 F12 或 Ctrl+Shift+I 打开。它不是黑客工具，而是每个开发者的"手术室"——本站特意不屏蔽右键和 F12，就是鼓励你大胆拆解。

二、Elements：看结构改样式

  • 鼠标移到页面元素上点右键 → "检查"，直接定位到它的 HTML。
  • 左侧是 DOM 树（结构），右侧是 Styles（应用的 CSS 规则）。
  • 可以在右侧临时改样式（比如把颜色改一下）——刷新前一直生效，是调样式的神器。
  • 左上角箭头按钮（Ctrl+Shift+C）可点选页面任意元素直接定位。

三、Console：看日志找报错

  • 红色 = 报错（点右侧文件名/行号跳过去）。
  • 黄色 = 警告（不致命但要注意）。
  • 你也可以直接在 Console 敲 JS 试运行，比如输入 1+1 回车。
// 判断一个元素存不存在
document.getElementById('xxx')  // 返回 null 就是没找到
typeof 42                        // "number"

四、Network：看网络请求

  • 打开 Network 面板后刷新页面，能看到每个文件（html/css/js/图片）的加载情况。
  • 红色条目 = 加载失败，Status 404 就说明文件路径错了——排查"样式没生效""图片裂了"必看。
  • 本站是静态站，你会看到 common.css、xd-features.js 等全部请求成功才算健康。

五、Sources 与断点

想知道"这段 JS 到底执行到哪一步了"，用断点：

Sources 面板打开要调试的 .js 文件。
点行号左侧设置断点（出现红点）。
重新触发该段代码（如点击按钮），执行会停在断点，逐行查看变量值。

调试按钮：继续、单步执行、进入/跳出函数。断点是排查"逻辑 bug"最有效的武器。

六、真机演练

  1. 打开本站任一页，F12 → Elements，用箭头工具点一下右上角"首页"链接，看看它的 HTML 和样式。
  2. Console 里输入 XD.progress.overall() 回车——能看到你的学习总进度（想不通的查 xd-features.js）。
  3. Network 刷新本页，确认 favicon.svg 等资源全部 200。
  4. 把页面缩到手机宽度（DevTools 里的设备模拟图标），体验响应式布局。
💡 记住口诀 "样式不对 → Elements 改着看；脚本报错 → Console 找行号；资源没加载 → Network 查 404；逻辑想不通 → Sources 下断点。"

本课小结

  • Elements 看结构改样式；Console 看日志找报错。
  • Network 查资源加载，红色条目=失败。
  • Sources 断点逐行调试，是排查逻辑 bug 的核心手段。
