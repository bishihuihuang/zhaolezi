## 二、推荐执行顺序（2 项，先低风险高收益）

### 【推荐】B. 23 页收藏数据导出/导入

**目标**：23 页词典用户数据可备份、可迁移、可跨设备恢复。

**修改文件**：
1. `工具脚本/rebuild_23.js` — 在 UI 面板加两个按钮：
   - **导出**：`JSON.stringify({version:2, favs, hist, exportedAt})` → `ZL.download('zhaolezi-dict-backup-YYYYMMDD.json', text, 'application/json')`
   - **导入**：`<input type="file">` 隐藏 + `<label>` 触发；解析后校验 `version===2`，与当前 favs/hist 合并（去重），成功后 `setFav/setHist` 触发渲染 + `ZL.toast('✅ 已导入 N 条收藏')`
2. 导出 UI 放 23 页已有的工具栏区域（与「中文反查」「全库搜索」并列）
3. 复用现有 `ZL.toast`、`ZL.download`，无新依赖

**验证**：
- 新增/扩展 `工具脚本/test_23_runtime.js`：注入 mock localStorage，模拟「导出→清空→导入」流程，断言 favs/hist 恢复、去重正确、非法 version 拒绝
- 混淆重生成 23.html，跑 `_冒烟自检.js`

### 【推荐】C. PWA 离线体验修复

**目标**：修复静态资源离线返回 undefined 的缺陷，加离线兜底页，让已缓存页面在离线时不白屏。

**修改文件**：
1. `service-worker.js`：
   - 修复 `fetch` L147-169 静态资源分支：网络失败时先 `caches.match(request)`，miss 才回落 `caches.match('./offline.html')`（替换当前的 `return undefined`）
   - `ASSETS` 追加 `'./offline.html'`
   - `CACHE_NAME` 升版 `'zhaolezi-v69'`
2. 新建 `_原始未混淆版/offline.html`：极简「您已离线，无法加载资源」提示页 + 「重试」按钮（`location.reload()`）
3. `工具脚本/_混淆工具.js`：注册 offline.html 为「不混淆」源→目标直拷路径
4. `_原始未混淆版/common.js:178` SW 注册块：版本号注释更新到 v69

**验证**：
- node 层校验 SW 语法（`node --check service-worker.js`）
- 集成测试 `_冒烟自检.js` 通过
- IAB 真机：断网打开 23 页 → 触发全库搜索 → 应看到 offline.html 兜底而非白屏

### 【可选】A. 23 页数据 gzip（需用户确认部署环境后再做）

**目标**：将 23data 分片从 22.56 MiB 明文降到 3-5 MiB 压缩传输。

**方案**（三选一，取决于部署）：
1. **纯静态托管（GitHub Pages/Cloudflare Pages 等）**：构建期产出 `.gz` 分片，客户端改 `fetch` 加 `Accept-Encoding: gzip` 并 `arrayBuffer`→`pako` 解包。需要引入 30KB 压缩库，或改用浏览器原生 `CompressionStream` 做反向（不适用 fetch 解码路径）。
2. **自带 Python 后端（8765）**：改 `ai_helper_server.py` 加 gzip，同时改 `_serve.js` 加 gzip；客户端 `loadLetter` 判断 `Content-Encoding: gzip` 后手动解码。
3. **只修 Cache-Control**：把 `_serve.js` 对 `.json` 从 `no-cache` 改为 `max-age=86400`，浏览器原生强缓存生效——零改动业务代码，但只解决重复访问，首次流量不变。

**阻塞点**：生产环境是什么？（纯静态托管 / 自带服务 / 二者并行）——需用户回答后才能定方案 1/2/3。
