一、没有版本控制的世界

回想一下你写文档的经历：

论文终稿.doc
论文终稿(2).doc
论文终稿(最终).doc
论文终稿(最终)(打死不改).doc
论文终稿(最终)(打死不改)(2).doc
最终版_真正最终版.doc   ← 崩溃现场

文件名后缀越来越长，却仍然搞不清：哪个是最新的？哪一版改了哪里？谁改的？怎么找回一周前的版本？这就是"没有版本控制"的日常。

二、版本控制是什么

版本控制（Version Control）是给文件"拍快照"的系统：每次你认为"这版值得记住"，就存一张快照，并附上时间、作者、改动说明。以后随时可以：

  • 回到任意一张历史快照（"我昨天改坏了我后悔了，回退！"）。
  • 对比任意两版差别（"这版到底删了什么？"）。
  • 多人协作互不踩踏（各改各的，最后合并）。
  • 在云端备份（本地电脑坏了，仓库还在）。
💡 一个类比 玩游戏时"存档/读档"你肯定熟悉。Git 就是给你所有重要文件（尤其是代码和网页）做无限存档位，还附带"这版发生了什么"的说明。

三、三区模型

Git 把工作分成三个区，理解它就懂了 70% 的命令：

工作区→ add → 暂存区→ commit → 版本库
区比喻对应命令
工作区你正在编辑的文件（桌面上的文件夹）改文件（不涉及 Git）
暂存区（Index）购物车：挑好了要"结算"的改动git add
版本库（Repository）仓库：正式归档的快照库git commit

为什么要"暂存"这一步而不是直接存？因为你能分批提交：今天改了两个功能，只想先归档其中一个，另一个继续改——购物车（暂存区）正好解决这个问题。

四、Git 是怎么诞生的

Git 是 Linux 之父 Linus Torvalds 在 2005 年为管理 Linux 内核而开发的分布式版本控制系统。它有两个核心特点：

  • 分布式：每个开发者电脑里都有一份完整仓库（不是只从中央服务器拿文件），离线也能提交，再同步到远程。
  • 快：处理海量文件依然迅捷，今天全世界几乎都在用它（GitHub 上的代码托管、开源协作全靠它）。

五、关键名词速览

名词含义
仓库 RepositoryGit 管理的项目文件夹（含隐藏的 .git 目录）
提交 Commit一张带说明的快照（版本）
分支 Branch并行的版本线（主线叫 main/master），可开新线实验再合并
远程 Remote托管在别处（如 GitHub）的仓库副本
推送/拉取 Push/Pull把本地提交传到远程 / 把远程更新拉回本地
克隆 Clone把远程仓库完整复制到本地

本课小结

  • 版本控制=给文件拍快照：随时回退、对比、协作、备份。
  • 三区模型：工作区（改）→ 暂存区（挑）→ 版本库（存）。
  • Git 是 Linus 为 Linux 内核写的分布式版本控制工具，是当今事实标准。
