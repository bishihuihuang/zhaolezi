一、文字进机器：先编号

计算机只认数字。让"字"进机器，就得先给每个字发一个身份证号（编码），再按号码存取。这套"字 ↔ 数字"的对照表，就是字符编码。一个问题随之而来：全世界这么多字，谁来编号？编号重复了怎么办？——这正是编码演进史的主线。

你打"中"→ 查编码表得数字→ 数字存进硬盘→ 读取时再查表还原"中"

二、ASCII：英文的起点

1963 年美国制定 ASCII（美国信息交换标准代码）：给英文字母、数字、常用符号分配编号，共 128 个字符，正好用 1 个字节（7 位有效）装下。

a9701100001

记两个规律：大写 A 是 65，小写 a 是 97（差 32），数字 0 是 48。到现在，这些编号仍然是谁都不能动的"地基"。

三、中文的本地编码：GBK

字符集只 128 个，装汉字远远不够——常用汉字就有 3000+。于是各国各搞各的：中国大陆制定了 GB2312 / GBK（简体中文，常用汉字用 2 字节 16 位表示），台湾有 Big5（繁体），日本有 Shift-JIS。

⚠️ 各说各话的代价 同一个二进制数字 D6D0，用 GBK 解是"中"，用 Big5 解是另一个字。跨地区传文件，就开始出现乱码。

四、Unicode：全球统一编号

1991 年，Unicode 联盟推出 Unicode（统一码）：给全世界所有字符分配唯一编号。比如 A = U+0041，"中" = U+4E2D，emoji 😀 = U+1F600。它只负责"编号"，不管"怎么存"。但存法必须统一——否则编号一样、存取规则不同还是会乱。

五、UTF-8：互联网事实标准

UTF-8 是 Unicode 的存储方案，也是当今互联网事实标准（本站每个页面都写着 UTF-8）。巧妙之处：

  • 兼容 ASCII：英文仍是 1 字节，和旧世界完全兼容。
  • 中文 3 字节：绝大多数汉字用 3 字节表示，根据首字节可自动判断字符长度。
  • 可变长：常用字符短、生僻字长，总体省空间。

六、乱码的真相与自救

🧩 乱码 = 用错编码表 乱码的本质是编码错配：文件用 UTF-8 写成，却被当成 GBK 打开，数字自然对不上号，于是出现"æµ‹è¯•"这类天书。

自救三招：

  • 换编码重开：记事本"文件 → 另存为"，下方"编码"选 UTF-8 保存；VS Code 右下角点编码 → "通过编码重新打开"。
  • 让工具自动识别：现代浏览器、编辑器多数能自动探测 UTF-8，乱码多补一个 <meta charset="UTF-8"> 就能好。
  • 统一规范：自己写文件、写网页一律 UTF-8，乱码与你无缘。
