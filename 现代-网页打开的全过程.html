一、一次完整的旅程

你在地址栏敲 example.com 回车，到屏幕上出现页面，经历了这八步：

① 输网址→ ② DNS 查 IP→ ③ 建立连接→ ④ 发请求→ ⑤ 服务器处理→ ⑥ 返回网页→ ⑦ 浏览器渲染→ ⑧ 加载子资源
  1. 输入并用 DNS 查 IP（C2 已讲）：拿到服务器的"真地址"。
  2. 建立 TCP 连接：客户端与服务器"三次握手"——好比打电话前的"喂？喂！听到了吗"，确认双方在线再开聊。
  3. 发送 HTTP 请求：浏览器说"你好，请把 / 这个页面给我"。
  4. 服务器处理并返回响应：返回状态码 + 一份完整网页（HTML 文本）。
  5. 浏览器渲染：把 HTML 解析成画面，再逐个请求图片、CSS、JS 等"子资源"。
  6. 等所有资源到齐，页面完整显示；进度条/转圈结束。

二、HTTP：网页世界的通用语

HTTP（超文本传输协议）是浏览器和服务器之间的"会话规则"，核心是一问一答：

请求（客户端 → 服务器）：
GET / HTTP/1.1
Host: example.com
User-Agent: Chrome/…

响应（服务器 → 客户端）：
HTTP/1.1 200 OK
Content-Type: text/html

<!DOCTYPE html><html>…（网页正文）

请求方法常见：GET（要数据）、POST（提交数据，如登录表单）。你看网页、刷抖音都是反复地 GET/POST。

三、状态码：服务器的暗号

状态码含义你遇到的表现
200成功正常打开
301 / 302重定向（网页搬家了）自动跳转到新地址
403禁止访问"无权访问该页面"
404找不到页面"404 Not Found"
429请求太频繁"太多请求，稍后再试"
500服务器内部错误"服务器出错了"，多半是站长那边的问题
503服务暂不可用（维护/过载）"维护中，请稍后"
💡 判断法 4xx 开头：多半是"你的请求"方面（404 拼错网址、403 没权限）；5xx 开头：是"服务器那边"出问题了——等一会儿或换个时间，跟你的电脑无关。

四、HTTPS：坐进加密车厢

HTTP 是明文的——中间人能看到你发的密码。 HTTPS = HTTP + TLS 加密：通信前握手交换密钥，之后内容全部加密传输，谁都偷看不了内容。

  • 浏览器地址栏的小锁 + "https://" 前缀 = 加密连接；输密码、支付一定要看这个锁。
  • 网站要加密，站长要在服务器配"SSL 证书"（现在有免费机构 Let's Encrypt）。
  • 看到"连接不安全"警告还硬闯的，风险自负——那正是没加密/证书异常的信号。

五、缓存：第二次为什么更快

第一次打开后，浏览器把图片、JS 等资源缓存在本地（本机磁盘）。第二次访问，直接读缓存，只请求变化的部分——这就是"第二次秒开"的原理。想强制刷新（拿到最新版）：Ctrl+Shift+R。

💡 本站自己的离线能力 本站是 PWA：首次打开后，Service Worker 把全部页面预缓存进本地（service-worker.js），之后断网也能看——缓存的进阶用法，G5 会带你打开控制台一探究竟。
